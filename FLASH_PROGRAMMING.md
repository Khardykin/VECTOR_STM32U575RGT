# Как прошить внешнюю flash (MX25K6435F): один этап или два?

Короткий ответ: **физически это одна процедура и одна команда, но две операции
записи** — сначала внутренняя flash (прошивка), затем внешняя (звуки). Отдельного
«второго этапа» на конвейере не нужно. Ниже три способа, от отладочного к производственному.

---

## Способ A. Программатор + external loader (отладка и мелкая серия)

STM32CubeProgrammer умеет писать внешнюю SPI-флеш через тот же SWD-порт, но для этого
ему нужен **external loader** — маленький `.stldr`-модуль, который загружается в RAM
STM32 и общается с чипом по SPI1.

Где взять loader:
- каталог установки: `.../STM32CubeProgrammer/bin/ExternalLoader/` — там лежат готовые
  (W25Qxxx, MX25L6406E, MX25L12835F и т.д.);
- ваш чип **MX25K6435F** в стоковом наборе может отсутствовать. Тогда варианты:
  1. взять loader от близкой модели той же семьи (MX25L6433E / MX25K6433F): базовый
     набор команд READ/PP/SE у них совпадает, но это нужно проверить чтением JEDEC;
  2. собрать свой `.stldr`: STM32CubeIDE → File → New → Project → **External Loader**
     (шаблон даёт каркас `Init/Read/Write/Erase/GetSectorInfo`; внутрь кладётся ваш
     же `spiflash.c`-код);
  3. не связываться с loader'ом и использовать способ B.

Команда одной строкой (обе записи в одной сессии):

```bat
STM32_Programmer_CLI -c port=SWD ^
   -w fw.bin 0x08000000 ^
   -el MX25K6435F.stldr -w sounds.img 0x90000000 -v ^
   -rst
```

`0x90000000` — базовый адрес внешней флеш, как его видит loader (у вашего loader'а
может быть другой базовый адрес — смотрите его описание). `-v` верифицирует запись.

Готовый bat-файл для цеха (`flash_prod.bat`):

```bat
@echo off
set CP="C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe"
%CP% -c port=SWD -w %1 0x08000000
if errorlevel 1 goto err
%CP% -c port=SWD -el %3 -w %2 0x90000000 -v
if errorlevel 1 goto err
%CP% -c port=SWD -rst
echo OK: прошивка и звуки записаны
goto eof
:err
echo ОШИБКА записи
:eof
```
Вызов: `flash_prod.bat fw.bin sounds.img MX25K6435F.stldr`.

Проверка после записи (чтение обратно и сверка с образом):

```bat
STM32_Programmer_CLI -c port=SWD -el MX25K6435F.stldr -r 0x90000000 65828 back.bin
fc /b sounds.img back.bin
```

## Способ B1. Звуки внутри прошивки, распаковка при первом старте (истинно один этап)

Образ звуков пакуется (LZ4/heatshrink, обычно 50–70% от исходного) и линкуется во
внутреннюю flash как const-блоб. Прошивка при первом старте (или по флагу «версия
звуков изменилась») сама разворачивает его во внешнюю flash через `extstore`.

Плюсы: ровно одна операция программатором, loader не нужен вообще.
Минусы: blob съедает внутреннюю flash (для 65 КБ звуков — ~40 КБ в сжатом виде);
при смене звуков перепрошивается всё устройство.

## Способ B2. Factory/OTA-режим прошивки (рекомендую для серии)

В прошивке добавляется сервисная команда: «принять sounds.img по сервисному UART
(у вас есть XS1 `EXT_TX/RX`) или позже по LTE/OTA и записать его во внешнюю flash
через `extstore`». Стенд на конвейере просто отдаёт файл в UART после прошивки MCU.

Плюсы:
- не нужен external loader и его поддержка;
- тем же кодом звуки обновляются в поле (OTA), без визита программатора;
- запись идёт через ваш же проверенный драйвер и `extstore` (CRC, карта разделов).

Минус: нужен протокол приёма (контрольная сумма, подтверждение) — ~150 строк.

**Рекомендация:** отладка сейчас — способ A (или вообще вручную через отладчик);
серия — способ B2; способ B1 держать в голове как запасной, если B2 не взлетит по срокам.

## Что уже защищает вас от «забыли прошить звуки»

Плеер при отсутствии/битости образа не молчит: срабатывает аварийный писк из
внутренней flash (`audio_beep`, см. AUDIO_MAP.md). То есть устройство, прошедшее
только этап «прошивка MCU», остаётся диагностически пригодным — бригада на линии
сразу слышит разницу между «нет звуков» и «не работает вообще».

## Карта адресов (напоминалка)

| Что | Где |
|---|---|
| прошивка MCU | внутренняя flash, 0x08000000 |
| sounds.img | внешняя flash, `SF_SOUNDS_BASE` = 0x000000 (см. `sfmap.h`) |
| конфигурация | внешняя, `SF_CONFIG_BASE` = 0x400000, кольцо 32×4 КБ |
| журнал | внешняя, `SF_LOG_BASE` = 0x420000, кольцевой |

Адреса в командах программатора (0x90000000 и т.п.) — это адреса **loader'а**, они не
обязаны совпадать с `SF_*` (которые считаются от начала чипа). Внутри прошивки всегда
используйте `SF_*`.
