# Звук: как запустить, как остановить, как поменять набор

Один документ про всю аудио-часть: управление плеером, набор звуков, сборка
образа, запись во внешнюю flash, диагностика. Архитектура и тактирование —
`SYSTEM.md`, мост UART — `UART_BRIDGE.md`.

---

## 1. Быстрая проверка: звук есть?


В `vector_config.h` по умолчанию:

```c
#define VECTOR_AUDIO_SELFTEST     3     /* три писка из ВНУТРЕННЕЙ flash до старта RTOS */
#define VECTOR_AUDIO_BOOT_PLAY    1     /* затем войти в состояние 0 -> звук по кругу   */
#define VECTOR_AUDIO_LOOP_STATE   1     /* звук состояния повторяется с паузой          */
#define VECTOR_AUDIO_LOOP_PAUSE_MS 500u
```

Прошиваете → включаете → **три писка** (проверка выходного тракта, внешняя
flash не участвует), затем `poeshl` (3.91 с), пауза 0.5 с, снова `poeshl` — и
так по кругу. В логе:

```
[0.01] 2/A: selftest: beep 3840 samples via SAI DMA (no queue, no ext flash)
[0.26] 2/A: selftest: done, hal_ms=240 (expected ~240) guard=1161699
[0.27] 2/A: image ok=1 sounds=3
[0.27] 2/A: boot: state 0, sound #0, loop=1 pause=500 ms
[0.28] 2/F: read 125004 b @84 ok, 51 ms
[0.28] 2/A: play #0 'poeshl' 62502 samples @16000 Hz
```

Три писка слышно, а `poeshl` нет → проблема в чтении образа (раздел 7).
Писков тоже нет → аналоговая часть (раздел 7.1).

## 2. Частота: 16 кГц, и она должна совпадать в трёх местах


| Где | Что стоит | Как менять |
|---|---|---|
| SAI1 | `SAI_AUDIO_FREQUENCY_16K` | CubeMX → SAI1 → Audio Frequency |
| Образ `sounds.img` | `--rate 16000` | `tools/pack_sounds.py ... --rate 16000` |
| Аварийный писк | `--rate 16000` | `tools/gen_beep.py --rate 16000` |
| Код | `AUDIO_SAMPLE_RATE 16000` | `audio_player.h` |

Если частота образа не совпадёт с SAI, плеер напечатает
`RATE MISMATCH: sound N Hz, SAI/AUDIO_SAMPLE_RATE M Hz` — звук при этом идёт с
другой скоростью и тоном.

**Предел длины звука** зависит от режима (раздел 3): со стримингом
ограничения на длину нет вовсе; без него (канал DMA в Normal mode) —
`AUDIO_BUF_SAMPLES = 65535` сэмплов = **4.09 с** при 16 кГц.

## 3. Стриминг через circular DMA


Прежняя схема читала звук **целиком** в RAM и отдавала одной DMA-транзакцией,
поэтому длина упиралась в 65535 сэмплов (предел `uint16_t Size` у
`HAL_SAI_Transmit_DMA`) и в 131 КБ RAM. Теперь звук идёт **кусками**:

```
        ap_buf[2 x CHUNK]  (CHUNK = 4096 сэмплов = 256 мс, всего 16 КБ RAM)
       +------------------+------------------+
 DMA → |     половина 0   |    половина 1    |  ← circular: дойдя до конца,
       +------------------+------------------+     DMA идёт снова с начала
              ▲                    ▲
   TxHalfCplt: половина 0    TxCplt: половина 1
   отыграла → поток пишет    отыграла → поток пишет
   в неё следующий кусок     в неё следующий кусок
              │                    │
              └── ext_read(смещение += CHUNK) + громкость + тишина в хвосте
```

* **ISR** (`HAL_SAI_TxHalfCpltCallback` / `HAL_SAI_TxCpltCallback`,
  GPDMA1_Channel11) только считает выданные сэмплы, ставит флаг «половина
  освободилась» и будит поток. Читать flash из ISR нельзя — там ожидание на
  мьютексе.
* **Поток** (`stream_service()`) дозагружает освободившуюся половину:
  `ext_read` куском 8 КБ (~3 мс по DMA), громкость, хвост добивается тишиной.
* Запас на дозагрузку = `CHUNK / 16000` = **256 мс** при стоимости чтения ~3 мс,
  то есть в ~80 раз. Если поток всё же не успеет, DMA повторит предыдущий
  кусок (слышно как заикание) и вырастет `audio_dbg_underrun`.
* Буфер `ap_buf` по умолчанию остаётся **полным** (`AUDIO_BUF_SAMPLES`,
  131 КБ), хотя стриминг использует только первые 16 КБ: если в кубе забыли
  `Mode = Circular`, плеер откатывается на одну транзакцию и должен уметь
  прочитать звук целиком. Когда стриминг подтверждён (в логе есть слово
  `stream`), ставьте `VECTOR_AUDIO_STREAM_SMALLBUF 1` — буфер урежется до двух
  кусков и освободит 115 КБ RAM.
* Конец звука определяется по `ap_st.played >= total`, а не по приходу TxCplt:
  в circular-режиме передача не завершается никогда. Хвост добивается тишиной,
  поэтому точность окончания — половина буфера (256 мс), щелчка нет.

### Что нужно включить в CubeMX (обязательно)

**SAI1_A → DMA Settings → GPDMA1 Channel11 → Mode = Circular.**

На U5 у GPDMA нет классического circular — он делается связным списком, и куб
генерирует `HAL_DMAEx_List_BuildNode()` + `HAL_DMAEx_List_SetCircularModeConfig()`,
после чего `hdmatx->Mode == DMA_LINKEDLIST_CIRCULAR`. Именно в этом режиме HAL
**не гасит SAI** по завершении блока (`SAI_DMATxCplt` проверяет
`hdma->Mode != DMA_LINKEDLIST_CIRCULAR`), поэтому стыки кусков проходят без
щелей и щелчков.

Плеер определяет режим сам. Если канал остался в Normal, стриминг не
включится, звук пойдёт старым путём одной транзакцией, а в лог один раз
напечатается:

```
SAI DMA is not circular -> one-shot mode, max 4.09 s per sound.
Set in CubeMX: SAI1_A -> DMA -> GPDMA1 Channel11 -> Mode = Circular
```

Переключатели: `VECTOR_AUDIO_STREAM` (1/0) и `VECTOR_AUDIO_STREAM_CHUNK`
(4096 сэмплов = 16 КБ RAM; меньше кусок → точнее конец звука и меньше RAM, но
меньше запас на дозагрузку).

`SND_STATE_DEFAULT_0/1` генерируются в `audio_ids.h` автоматически.

## 5. Управление


### Состояния и цикл

Плеер живёт в одном из состояний (`ap_state = 0..2`), состоянию назначен звук
таблицей `ap_state_map[]` в `audio_player.c`:

| состояние | звук | длительность | поведение |
|---|---|---|---|
| 0 | `SND_STATE_DEFAULT_0` = `SND_B_CLICK` | 0.06 с | играет; при `VECTOR_AUDIO_LOOP_STATE=1` — по кругу |
| 1 | `SND_STATE_DEFAULT_1` = `SND_C_VOICE_GAS` | 2.20 с | то же |
| 2 | `AP_STATE_SND2` = `SND_D_MYVOICE` | **8.10 с** | то же; **требует стриминга** (раздел 3) |

`SND_STATE_DEFAULT_0/1` генерирует `pack_sounds.py` (первые два звука образа).
Третье состояние — `AP_STATE_SND2`, индекс третьего звука; если в образе
меньше трёх звуков, он равен `AUDIO_STATE_SILENT` (0xFFFF) — «пустая ячейка»,
цикл не взводится. Проверка на состав образа делается на этапе компиляции
(`ap_state_assert0/1/2`), поэтому при пересборке образа с двумя звуками
сборка не сломается, а состояние 2 само станет тишиной.

Без третьего состояния самый длинный звук был бы вообще недостижим с кнопки
(`BUTTON1` крутит 0→1→2→0), и проверить стриминг 8-секундной дорожкой было бы
нечем.

```
audio_set_state(0) ─► ap_state=0 ─► start_now(b_click) ─► SAI DMA ─► динамик
                                          │
                     (доиграл: GPDMA1_Channel11 → ISR → семафор)
                                          ▼
                              пауза 500 мс ─► снова start_now(b_click) ─► ...
```

Пауза выдерживается таймаутом `tx_semaphore_get`, поэтому любая команда
прерывает её **мгновенно** — стоп во время паузы не ждёт.

### API

Звать можно **из потока и из ISR**: функции кладут команду в очередь ThreadX и
взводят семафор. Работу делает один поток `Audio Player`.

| Функция | Что делает | Возврат |
|---|---|---|
| `audio_set_state(st)` | смена режима: текущий звук прерывается, играется звук состояния `st`; `st=2` = тишина | — |
| `audio_play(id)` | одноразовый звук: если свободно — сразу, иначе после текущего | `audio_err_t` |
| `audio_play_name("poeshl")` | то же, поиск по имени в таблице образа | `audio_err_t` |
| `audio_stop()` | **полный стоп**: звук + очередь + отложенный + цикл | — |
| `audio_beep()` | аварийный писк из внутренней flash | — |
| `audio_selftest()` | писк напрямую, без очереди/потока/состояний (можно из `main()` до RTOS) | 0/1/2 |
| `audio_set_loop(1/0)` | включить/снять цикл (текущий повтор доиграет) | — |
| `audio_set_loop_pause(ms)` | пауза между повторами | — |
| `audio_set_volume(0..100)` | громкость, применится со следующего звука | — |
| `audio_get_state/loop/volume/loop_pause()` | прочитать | — |
| `audio_count()`, `audio_name(i)`, `audio_image_ok()`, `audio_reload_image()` | справка по образу | — |

`audio_err_t`: `0` OK, `1` нет образа, `2` неверный индекс, `3` звук длиннее
буфера, `4` ошибка чтения flash или запуска DMA, `5` очередь полна.

### Как остановить

| Вызов | Эффект |
|---|---|
| `audio_stop()` | всё: звук, очередь, отложенный звук и **цикл** |
| `audio_set_state(2)` | состояние «тишина» (запоминается в `ap_state`) |
| `audio_set_loop(0)` | цикл снять, текущий повтор доиграет |

Кнопкой: `BUTTON3` = стоп, `BUTTON1` до состояния 2 = тишина.
Снова включить: `audio_set_state(0)`.

### Кнопки (`VECTOR_AUDIO_DEMO_KEYS = 1`)

| Кнопка | Пин | Действие |
|---|---|---|
| BUTTON1 | PB1 | цикл состояний `0 → 1 → 2 → 0`, звук нового состояния стартует сразу |
| BUTTON2 | PB2 | следующий звук образа по кругу |
| BUTTON3 | PB3 | стоп |

Пиновская конфигурация — из CubeMX (`RISING_FALLING` + `PULLUP`). Активный
уровень обязан ей соответствовать: при pull-up `VECTOR_KEY_PRESSED_LEVEL = 0`.
Если перепутать, звук стартует по **отпусканию** кнопки. Антидребезг
`VECTOR_KEY_DEBOUNCE_MS = 50`, отсчёт свой на каждую кнопку.

### Пример рабочего кода

```c
#include "audio_player.h"

if (gas >= GAS_ALARM) {
    if (audio_get_state() != 0) audio_set_state(0);   /* poeshl по кругу */
    audio_play(SND_C_VOICE_GAS);                      /* подсказка поверх цикла */
} else if (gas >= GAS_WARN) {
    if (audio_get_state() != 1) audio_set_state(1);   /* b_click */
} else {
    if (audio_get_state() != 2) audio_set_state(2);   /* ТИШИНА */
}
```

`audio_set_state()` дёргайте только при **смене** уровня, иначе звук будет
обрываться и начинаться заново (смена состояния прерывает текущий).

## 6. Как пересобрать образ


Три шага из корня проекта (Python 3, только стандартная библиотека):

В **Windows** пишите команду в одну строку: символ `\` переносит строку только
в bash, а cmd.exe передаст его как имя файла (скрипт теперь такой аргумент
отбрасывает с подсказкой, но лучше не проверять).

```bat
python tools/pack_sounds.py tools/b_click.wav tools/c_voice_gas.wav tools/d_myvoice.wav --rate 16000 --gain 1.0 --out tools/sounds.img

# 2. тот же образ как const-массив во внутренней flash (для factory-режима)
python tools/bin2c.py tools/sounds.img --out Core/VectorLib/Audio/Src/audio_factory_image.c

# 3. если меняли частоту - перегенерировать писк
python tools/gen_beep.py --rate 16000
```

**Шаг 2 обязателен после каждого шага 1**, иначе во внешнюю flash запишется
прошлая сборка: `audio_factory_image.c` — это и есть то, что физически
линкуется в прошивку и программируется в чип. Проверить, что файлы в синхроне:
заголовок `audio_factory_image.c` содержит `/* источник: sounds.img, N байт */`,
N должен равняться размеру `tools/sounds.img`.

Порядок файлов в команде = индексы звуков. Скрипт сам сводит в моно, приводит
к `--rate`, применяет `--gain`, считает CRC32 каждого блока и таблицы, пишет
`tools/sounds.img.manifest.txt` (паспорт сборки с sha256 и точной командой для
воспроизведения) и `Core/VectorLib/Audio/Inc/audio_ids.h`.

Полезные режимы:

```bash
python3 tools/pack_sounds.py --info tools/*.wav     # параметры WAV без сборки
python3 tools/pack_sounds.py tools/sounds.img --check   # распарсить готовый образ
```

Требования к WAV: 16 бит/сэмпл; каналы сводятся в моно; частота приводится к
`--rate`. Ограничение 4.09 с действует только без стриминга (раздел 3).

### Как образ попадает во внешнюю flash

| Способ | Когда | Что делать |
|---|---|---|
| **Factory-режим прошивки** (сейчас) | отладка, мелкая серия | ничего: образ (324 КБ) линкуется в прошивку и записывается во внешнюю flash при первом старте, а также когда он там отсутствует, испорчен или **устарел** (`VECTOR_AUDIO_FACTORY_EMBED`, `_ON_BOOT`, `_UPDATE`) |
| Программатор + external loader | производство | ST-LINK + `.stldr`-лоадер для MX25R, шить `tools/sounds.img` в адрес `0x000000` внешней flash |
| OTA по LTE | позже | образ в файл, `sf_sector_erase` + `sf_program` через `extstore`, затем `audio_reload_image()` |

### Три причины перезаписать внешнюю flash

`load_image()` принимает образ только если совпали magic/version/count, CRC32
таблицы **и** частота каждого звука с `AUDIO_SAMPLE_RATE`. Но валидности мало:
образ может быть валидным и при этом **устаревшим**. Поэтому перезапись
запускается в одном из трёх случаев (и всегда не больше одного раза за старт):

| № | Условие | Что в логе | Флаг |
|---|---|---|---|
| 1 | образа нет / битый заголовок / CRC таблицы не сошёлся | `image header bad: magic=ffffffff` или `image CRC mismatch` | `ap_img_ok = 0` |
| 2 | частота звука ≠ `AUDIO_SAMPLE_RATE` | `image rate mismatch: 3 of 3 sounds are not 16000 Hz -> reprogram` | `ap_img_ok = 0` |
| 3 | **образ валиден, но это другая сборка**, чем зашита в MCU | `factory: flash image is STALE (flash size=197456 crc=b6a8cb90 n=3, embedded size=331808 crc=369c043a n=3)` → `image stale -> factory UPDATE (takes seconds)` | `ap_img_stale = 1` |

Случай 3 добавлен потому, что без него **пересборка `sounds.img` не попадала во
внешнюю flash вообще никогда**: старая сборка проходит все проверки
(magic/CRC/частота в порядке), `ap_img_ok = 1`, и factory-ветка
`if (!ap_img_ok)` не срабатывала. В логе это выглядело так — новый образ уже
без `poeshl`, а устройство играет именно его:

```
image ok=1 sounds=3
play #0 'poeshl' 62502 samples @16000 Hz     <-- СТАРЫЙ набор из внешней flash
```

Отпечаток (fingerprint) = `total_size` + `count` + `table_crc32` из заголовка.
`table_crc32` покрывает всю таблицу, а в каждой записи лежат имя, смещение,
длина, частота и CRC32 своего PCM-блока — поэтому любое изменение набора
звуков (добавили / убрали / пересобрали wav / поменяли порядок файлов в
команде) меняет отпечаток. Сравнение делает `audio_factory_is_stale()`
(`audio_factory.c`), это чтение 24 байт const-памяти, шину SPI не трогает.

Полный лог первого старта после пересборки:

```
factory: flash image is STALE (flash size=197456 crc=b6a8cb90 n=3, embedded size=331808 crc=369c043a n=3)
image ok=1 stale=1 sounds=3
image stale -> factory UPDATE (takes seconds)
factory: programming 331808 b (81 sectors), takes seconds
factory: erased up to sector 0
...
factory: done, 331808 b written and verified
factory ok, sounds=3 stale=0
image ok=1 stale=0 sounds=3
```

Все следующие старты — `image ok=1 stale=0 sounds=3` и **ни одной записи**:
отпечатки совпали, внешняя flash не трогается, износа нет.

### Переключатели factory-режима

| Макрос (`vector_config.h`) | По умолч. | Смысл |
|---|---|---|
| `VECTOR_AUDIO_FACTORY_EMBED` | 1 | линковать `sounds.img` во внутреннюю flash как const-массив |
| `VECTOR_AUDIO_FACTORY_ON_BOOT` | 1 | разрешить автоматическую запись при старте (случаи 1–3) |
| `VECTOR_AUDIO_FACTORY_UPDATE` | 1 | сравнивать отпечатки и обновлять устаревший образ (случай 3) |
| `VECTOR_AUDIO_FACTORY_FORCE` | 0 | **отладка**: перезаписывать внешнюю flash на каждом старте |
| `VECTOR_AUDIO_FACTORY_VERIFY_RETRY` | 3 | сколько раз повторять сбойное чтение при верификации (защита от транзиентных таймаутов SPI под отладчиком, 1..16) |

Гарантия «никогда не трогать внешнюю flash»: `VECTOR_AUDIO_FACTORY_ON_BOOT 0`
— тогда при невалидном образе плеер пищит и печатает причину, при устаревшем —
играет старый набор с предупреждением `image stale, factory OFF by config ->
playing OLD set`, а запись делает программатор или ваш вызов
`audio_factory_program()`.

Factory-запись стирает столько секторов, сколько занимает встроенный образ
(331808 Б → 81 сектор), пишет и верифицирует побайтово — единицы секунд.
Если новый образ короче старого, хвост старых данных остаётся нестёртым: это
безвредно, чтения ограничены `total_size` из нового заголовка.

### Верификация и транзиентные сбои чтения (`VECTOR_AUDIO_FACTORY_VERIFY_RETRY`)

Верификация читает образ обратно кусками по 256 Б **блокирующим опросом SPI**
(256 Б < `VECTOR_SPI_DMA_MIN_LEN` = 1024, поэтому DMA здесь не участвует). Под
отладчиком ядро периодически останавливается на Live Watch / Expressions
refresh, и обмен, попавший на такой halt, возвращается по таймауту HAL:

```
read 256 b @7700 FAIL st=3 (0 b done)      <-- st=3 = HAL_TIMEOUT, 0 байт
factory: verify read fail at 30464
factory FAILED -> beep only
```

Это **сбой чтения, а не порча записи**: к этому моменту все секторы уже
запрограммированы (в логе выше — `write 4096 b @... ok` для всех 82 секторов),
споткнулось одно чтение при сверке. Раньше один такой глюк обрывал всю
factory-запись, и плеер уходил в `beep only`, хотя образ во внешней flash цел.

Сделано две защиты:

1. **Повтор сбойного чтения.** Каждый верификационный кусок читается до
   `VECTOR_AUDIO_FACTORY_VERIFY_RETRY` раз (по умолчанию 3) с коротким сном
   RTOS между попытками. Реальное расхождение байт (`MISMATCH`) **не**
   ретраится — это уже не глюк, а порча, она возвращается отдельным кодом.
2. **Решение по факту, а не по коду возврата.** `ap_thread_entry` после
   `audio_factory_program()` **всегда** перечитывает образ
   (`audio_reload_image()`) и решает «играть или beep only» по валидности
   перечитанного образа, а не по коду возврата записи.

Коды возврата `audio_factory_program()`:

| Код | Значение | Что делает плеер |
|---|---|---|
| `0` | записано и верифицировано | играет образ |
| `-1` | стирание/запись не удались | перечитывает; образа нет → `beep only` |
| `-2` | верификация нашла **расхождение** байт | образу не доверяет → `beep only` |
| `-3` | верификация не **прочитала** кусок после повторов | перечитывает; образ цел → играет, в лог `factory verify glitch rc=-3, image reloaded OK` |

Лог успешного восстановления после транзиентного сбоя:

```
factory: verify read retry 1 at 30464
factory: done, 331808 b written and verified
factory ok, sounds=3 stale=0
```

или, если сбой случился уже после записи и повтор не помог, но образ цел:

```
factory: verify read fail at 30464 after 3 tries
factory verify glitch rc=-3, image reloaded OK, sounds=3
```

> **Это симптом отладчика, не железа.** Тот же halt ядра объясняет строки
> `core ran 50% of wall` в `clk meas` (см. `SYSTEM.md`, раздел 7.2). В
> свободном прогоне (Run, без Live Watch) верификация проходит без повторов.
> Если `factory verify glitch` / `read ... FAIL st=3` повторяются **в каждом**
> старте и в свободном прогоне — это уже не halt: проверяйте питание flash,
> линии SPI и `SF_TIMEOUT_MS`.

> **Внутренняя flash.** STM32U575RG = 1 МБ. Образ 331808 Б ложится в
> `audio_factory_image.c` как есть (не текстом), плюс остальная прошивка.
> Если линкер скажет `region FLASH overflowed` — ставьте
> `VECTOR_AUDIO_FACTORY_EMBED 0` и шейте `tools/sounds.img` программатором.

### Карта внешней flash (8 МБ, `sfmap.h`)

```
0x000000  SOUNDS  4 МБ   sounds.img целиком (заголовок 24 Б + таблица 36 Б/звук + PCM)
0x400000  CONFIG  4 КБ   одна страница: записи добавляются без стирания, свежая = max seq
0x401000  LOG     ~3.9 МБ кольцевой журнал секторами по 4 КБ
0x800000  конец
```

Области не пересекаются и выровнены на 4 КБ, поэтому стирание в одной физически
не может задеть соседнюю.

## 7. Диагностика


### 7.1 Писков нет вообще → аналоговая часть

`audio_selftest()` доказывает всю цифровую цепочку: `HAL_OK` от
`HAL_SAI_Transmit_DMA` + возврат SAI в `READY` + `done, hal_ms=240` означают,
что SAI **реально вытактировала** все сэмплы на PA8/PA9/PA10 с правильной
частотой (DMA не завершилась бы, не запроси SAI данные). Данные не нулевые:
пик ±18000 из ±32767.

| № | Проверить | Норма |
|---|---|---|
| 1 | PC9 (`SD_MODE`) мультиметром | ~3.3 В. При 0 В усилитель в shutdown — звука не будет никогда |
| 2 | Питание усилителя (VDD) | по схеме; возможно включается отдельным пином |
| 3 | PA8→BCLK, PA9→LRC, PA10→DIN | осциллограф: 512 кГц / 16 кГц / данные (при 16 кГц, 2 слота по 16 бит) |
| 4 | Что за микросхема | MAX98357A: SD_MODE + GAIN. PCM5102/TAS: нужен **XSMT/MUTE = high**, часто ещё SCK — при висящем XSMT звука нет при полностью рабочем I2S |
| 5 | Формат I2S | SAI = I2S standard (данные сдвинуты на 1 BCLK), 16 бит, 2 слота. DAC, ждущий left-justified, даст тишину или искажения |
| 6 | Динамик, общая земля | 4–8 Ом, не оборван |

Без осциллографа: щёлкните `SD_MODE` 0→1 — в динамике должен быть щелчок. Нет
щелчка → усилитель не запитан или это не тот пин.

### 7.2 Писки есть, звука из образа нет

| Симптом | Причина |
|---|---|
| `image header bad: magic=ffffffff` | область SOUNDS пуста (стёрта). Запустится factory-запись |
| `image CRC mismatch: got .. want ..` | образ повреждён/недописан; пересоберите и перезапишите |
| `RATE MISMATCH` | образ собран с другой частотой, чем SAI (раздел 2) |
| `sound #N too long: X samples > 65535` | звук длиннее 4.09 с при 16 кГц → раздел 9 |
| `flash probe FAIL` / jedec не `c2 28 17` | внешняя flash не отвечает: SPI1, CS PA4, питание |
| `SAI DMA fail: hal=2` | SAI занята (`HAL_BUSY`) — не было `HAL_SAI_Abort` |
| `play #... stream ...` есть, `audio_dbg_played` растёт, звука нет | аналоговая часть, раздел 7.1 |
| `SAI DMA is not circular -> one-shot mode` | в кубе не выставлен `Mode = Circular` для GPDMA1 Channel11 (раздел 3) |
| `audio_dbg_underrun` растёт | поток не успевает дозагрузить половину за 256 мс: кто-то долго держит `ext_mtx` (стирание сектора) или мало `VECTOR_AUDIO_STREAM_CHUNK` |
| `audio_dbg_stuck > 0` | не пришёл колбэк завершения SAI-DMA: `GPDMA1_Channel11_IRQn` |
| `factory FAILED rc=-3 -> beep only` | верификация не прочитала кусок даже после `VECTOR_AUDIO_FACTORY_VERIFY_RETRY` повторов, и образ не перечитался. Чаще всего halt ядра отладчиком; повторите старт в свободном прогоне (Run, без Live Watch) |
| `factory FAILED rc=-2 -> beep only` | верификация нашла реальное расхождение байт — запись действительно не удалась. Проверьте питание flash и линии SPI, пересоберите образ |
| `factory verify glitch rc=-3, image reloaded OK` | **не ошибка**: одно чтение верификации сорвалось (транзиентный таймаут SPI), но образ перечитан и валиден — звук будет играть. См. раздел 6 |

### 7.3 Точка останова в `start_now()` не срабатывает

`start_now()` вызывается только из потока `Audio Player` и только по команде:

1. `VECTOR_AUDIO_BOOT_PLAY` = 3 → при старте вызывается `beep_now()`, а не
   `start_now()`. Поставьте 1.
2. `audio_dbg_boot_stage` — должно быть 5 (рабочий цикл); 2/4 = образа нет.
3. `demo_dbg_edges` / `demo_dbg_press` — доходят ли кнопки; `press=0` при
   растущем `edges` = не совпал активный уровень с подтяжкой.
4. `audio_dbg_keys` / `audio_dbg_last_cmd` — дошла ли команда (3 = state,
   1 = play, 2 = stop, 4 = beep).
5. `audio_dbg_wakes`/`timeouts` растут — поток жив, событий просто нет.

### 7.4 Счётчики (Expressions)

| Переменная | О чём |
|---|---|
| `sf_jedec[3]`, `sf_probe_rc` | жива ли внешняя flash (`C2 28 17`, `rc=0`) |
| `audio_dbg_boot_stage` | 1 образ найден, 2 нет, 3 factory ok, 4 factory провален, 5 рабочий цикл |
| `audio_dbg_keys`, `_last_cmd` | команды доходят до плеера |
| `audio_dbg_started`, `_played` | старт DMA / доиграно |
| `audio_dbg_loops` | сколько повторов цикла сыграно |
| `audio_dbg_errors`, `_last_err` | код `audio_err_t` или `0x1000|SAI.ErrorCode` |
| `audio_dbg_stuck` | звук добит watchdog'ом (нет колбэка DMA) |
| `audio_dbg_dropped` | `play` вытеснил предыдущий отложенный `play` |
| `sf_dbg_dma_chunks`, `_fallback`, `_tmo` | чтение по DMA и откаты на опрос |
| `factory_dbg_sector` | прогресс заводской записи |

## 9. Ограничения и что дальше


* **Длина звука не ограничена** при включённом стриминге (раздел 3). Без
  него — 65535 сэмплов = 4.09 с при 16 кГц.
* Одновременно звучит только один звук: буфер один.
* RAM при стриминге — 16 КБ используется (2 × 4096 сэмплов), но буфер по
  умолчанию остаётся полным (131 КБ) ради one-shot fallback;
  `VECTOR_AUDIO_STREAM_SMALLBUF 1` возвращает 115 КБ.
* Точность окончания звука — половина буфера (256 мс при CHUNK = 4096): хвост
  добивается тишиной.
* Что можно улучшить дальше:
  1. **IMA-ADPCM** (в образе зарезервирован `AUDIO_FMT_ADPCM_IMA = 1`) — в 4
     раза меньше трафика по SPI и в 4 раза больше звуков во внешней flash;
     нужен декодчик в `stream_fill()`.
  2. **Предзагрузка** следующего звука очереди, пока играет текущий (второй
     буфер), чтобы стык в цепочке фраз был мгновенным.
  3. Микширование двух дорожек (сигнал + подсказка) — сейчас только
     последовательное воспроизведение.
* Пауза цикла выдерживается с точностью тика RTOS (10 мс) плюс время чтения
  звука из flash (~50 мс для 125 КБ по DMA).
* Длинные записи (минуты) — только стриминг.
