# Звук: как запустить, как остановить, как поменять набор

Плеер играет PCM-образы из внешней SPI flash **MX25R6435F** (8 МБ) через
SAI1 (I2S) → оконечный усилитель типа **MAX98357A** (SD_MODE = PC9).

* **44.1 кГц, 16 бит, моно** — качество «компакт-диска» по полосе и разрядности
  (почему это потолок тракта — раздел 2).
* Образ `sounds.bin` во внешнюю flash записывает **программатор** через
  external loader: [docs/FLASHING.md](FLASHING.md). Прошивка внешнюю flash
  **не программирует никогда** — factory-режим и встроенный образ удалены.
* Прошивка MCU и образ звуков живут в разных памятях и обновляются независимо.

```
tools/*.wav ──pack_sounds.py──▶ tools/sounds.bin ──ST-LINK + ExtLoader──▶ MX25R6435F (0x0)
                                                                               │
кнопки/API ──▶ очередь ──▶ поток "Audio Player" ──ext_read кусками──▶ буфер ──▶ SAI1 DMA (circular) ──▶ усилитель
```

---

## 1. Быстрая проверка: звук есть?

По умолчанию прошивка при старте молчит (`VECTOR_AUDIO_SELFTEST 0`,
`VECTOR_AUDIO_BOOT_PLAY 0`) и ждёт команд. Для проверки тракта на время
отладки:

```c
#define VECTOR_AUDIO_SELFTEST     1     /* один писк из ВНУТРЕННЕЙ flash до старта RTOS */
#define VECTOR_AUDIO_BOOT_PLAY    3     /* затем ещё писк уже через поток               */
```

* Писка нет вообще → аналоговая часть/SAI/DMA: чек-лист в разделе 7.1.
* Писк есть, звуки образа не играют → образ во внешней flash: разделы 6 и 7.2.
* В логе старта обязательно должна быть строка `image ok=1 sounds=5`.

## 2. Качество звука: 44.1 кГц / 16 бит — и почему не «24 бита»

Выходной тракт: SAI1 (I2S, 16-битные слова) → MAX98357A → динамик.
Усилитель поддерживает **8–96 кГц и 16/24/32 бита** I2S, то есть упираемся не
в него, а в исходники и здравый смысл:

| Что улучшает звук | Почему |
|---|---|
| **44.1 кГц вместо 16 кГц** (сделано) | 16 кГц режет полосу до 8 кГц — «телефонный» глухой звук. 44.1 кГц даёт полную слышимую полосу 20 Гц–20 кГц; главная слышимая разница |
| 16-битные исходники (уже так) | 96 дБ динамического диапазона — выше, чем у самого усилителя/динамика |
| 24/32 бита в I2S | **Не даёт ничего**, если исходник 16-битный: младшие биты заполняются нулями. Имеет смысл только при 24-битных мастер-файлах |
| Апсемплинг 16 кГц → 44.1 кГц | **Не возвращает** срезанные когда-то верха. Качество = качество мастер-файла |

**Вывод:** держите мастер-файлы в 44.1 кГц/16 бит (или выше — pack_sounds
приведёт к 44.1 кГц). Всё, что было записано в 16 кГц, нужно
пересоздать из оригиналов (запись голоса, TTS-генерация), а не апсемплить.

Цена 44.1 кГц: поток 88.2 КБ/с (SPI1 @ 20 Мбит/с загружен на ~4%),
8 секунд звука ≈ 706 КБ flash (в область SOUNDS 4 МБ влезает ~47 с),
RAM — те же 16 КБ (стриминг).

### Частота задаётся в четырёх местах — они обязаны совпадать

| Где | Что стоит | Как менять |
|---|---|---|
| SAI1 | `Audio Frequency = 44.1 kHz` | CubeMX → SAI1 → Audio Frequency. **Сама по себе эта настройка частоту не даёт**: нужен ещё подходящий PLL3 — см. «Тактирование SAI1» ниже |
| Ядро SAI1 (PLL3P) | `22.579210 МГц` = 512 × 44100 | CubeMX → Clock Configuration → PLL3 (N=12, FRACN=5741, P=9, M=1) |
| Код | `AUDIO_SAMPLE_RATE 44100` | `audio_player.h` |
| Образ `sounds.bin` | `--rate 44100` | `tools/pack_sounds.py` (теперь это значение по умолчанию) |
| Аварийный писк | `--rate 44100` | `tools/gen_beep.py` (по умолчанию 44100; `audio_beep.c` уже перегенерирован) |

При несовпадении плеер отвергает образ целиком:
`image rate mismatch: N of M sounds are not 44100 Hz -> rebuild image and reprogram flash`.

### Тактирование SAI1: как получить ровно 44100 Гц

SAI в режиме master делит своё ядро **только нацело**:

```
FS = SAI_CK / (256 × MCKDIV),   MCKDIV = 1..63 (целое)
```

`MCKDIV` прошивка не задаёт — его считает HAL из `Init.AudioFrequency`
(`stm32u5xx_hal_sai.c`: `MCKDIV = round(SAI_CK / (FS × 256 × OSR))`, у нас
`OSR = 1`, т.к. `MckOverSampling` выключен). Отсюда жёсткое требование:

> **SAI_CK обязан быть кратен 256 × 44100 = 11.2896 МГц**:
> 11.2896, 22.5792, 33.8688, 45.1584, … МГц

**Почему раньше было −2.34 %.** PLL3 был настроен на «красивые» 44.1 МГц
(N=13, FRACN=6400, P=5) — это ровно 1000 × 44100, но 1000 не делится на 256.
HAL брал ближайший целый делитель `MCKDIV = 4` и получал
`FS = 44.1 МГц / 1024 = 43 066.4 Гц`: **−2.344 %** (−41 цент, звук ниже и
длиннее на 2.4 %: файл 4.00 с звучал 4.096 с). CubeMX это честно показывал в
`.ioc`: `SAI1.RealAudioFreq = 43.066 KHz`, `SAI1.ErrorAudioFreq = -2.34 %`.

**Текущая настройка** (`sai.c` → `HAL_SAI_MspInit` и те же числа в `.ioc`):

| Параметр | Значение | Комментарий |
|---|---|---|
| Источник PLL3 | HSE 16 МГц | не меняли |
| `PLL3M` | 1 | PFD3 = 16 МГц → `RCC_PLLVCIRANGE_1` не меняем |
| `PLL3N` | 12 | было 13 |
| `PLL3FRACN` | 5741 | было 6400; дробная часть = 5741/8192 |
| `PLL3P` | 9 | было 5 |
| VCO3 | 203.212891 МГц | в допустимых 96…344 МГц |
| **SAI_CK (PLL3P)** | **22.579210 МГц** | = 512 × 44100 |
| `MCKDIV` (считает HAL) | 2 | |
| **FS** | **44 100.0197 Гц** | **+0.44 ppm** = 0.008 цента; 1 с расхождения за ~630 ч |

Ровно 44 100.000 Гц из 16 МГц не получается в принципе: 44100 = 2²·3²·5²·7²,
а шаг дробной части PLL — 1/8192 (степень двойки). Поэтому цель — единицы ppm,
это на слух и на длительность не влияет никак.

Другие рабочие варианты (если нужен иной VCO/делитель; ограничения U5:
VCO3 96…344 МГц, PFD3 4…16 МГц, N 4…512, P 1…128, FRACN 0…8191):

| `PLL3N` | `PLL3FRACN` | `PLL3P` | SAI_CK, МГц | MCKDIV | FS, Гц | ppm |
|---|---|---|---|---|---|---|
| 20 | 3788 | 29 | 11.289601 | 1 | 44 100.004 | +0.09 |
| 15 | 4286 | 22 | 11.289595 | 1 | 44 099.981 | −0.44 |
| **12** | **5741** | **9** | **22.579210** | **2** | **44 100.020** | **+0.44** ← выбрано |
| 14 | 918 | 5 | 45.158594 | 4 | 44 100.191 | +4.34 (минимальная правка: `PLL3P` не меняется) |

**Как проверить на железе.** В логе старта должна быть строка (добавлена в
`audio_init()`):

```
sai ck=22579210 Hz mckdiv=2 fs=44100.020 Hz (need 44100)
```

`fs` отличается от 44100 больше чем на пару Гц → PLL3 в кубе настроен не на
ту частоту. Без лога — осциллографом: PA9 (FS) = 44 100.0 Гц,
PA8 (SCK) = 1 411 200 Гц (= 32 × FS, кадр I2S 16 бит × 2 слота).

## 3. Стриминг через circular DMA

Звук идёт **кусками**, длина не ограничена ни буфером, ни `uint16_t Size`:

```
        ap_buf[2 x CHUNK]  (CHUNK = 4096 сэмплов = 93 мс @44.1к, всего 16 КБ RAM)
       +------------------+------------------+
 DMA → |     половина 0   |    половина 1    |  ← circular: дойдя до конца,
       +------------------+------------------+     DMA идёт снова с начала
              ▲                    ▲
   TxHalfCplt: половина 0    TxCplt: половина 1
   отыграла → поток пишет    отыграла → поток пишет
   в неё следующий кусок     в неё следующий кусок
              │                    │
              └── ext_read(смещение += CHUNK) + громкость + тишина в хвосте
```

* **ISR** (`HAL_SAI_TxHalfCpltCallback` / `HAL_SAI_TxCpltCallback`,
  GPDMA1_Channel11) только считает выданные сэмплы, ставит флаг «половина
  освободилась» и будит поток. Читать flash из ISR нельзя — там мьютекс.
* **Поток** (`stream_service()`) дозагружает освободившуюся половину:
  `ext_read` куском 8 КБ (~3 мс по DMA), громкость, хвост добивается тишиной.
* Запас на дозагрузку = `CHUNK / 44100` = **93 мс** при стоимости чтения
  ~3 мс, то есть в ~30 раз. Не успел — DMA повторит предыдущий кусок (слышно
  как заикание) и вырастет `audio_status.cnt_underruns`.
* `VECTOR_AUDIO_STREAM_SMALLBUF` теперь **1 по умолчанию**: буфер плеера =
  2 куска (16 КБ RAM). Circular-режим задан в `.ioc`
  (GPDMA1.CIRCULARMODE_GPDMACH11=ENABLE), поэтому запасной путь «одной
  транзакцией» (он потребовал бы полный буфер 131 КБ и ограничил бы звук
  1.49 с) практически недостижим; если в кубе всё же сбросить Mode = Normal,
  плеер напечатает подсказку в лог, а длинные звуки вернут
  `AUDIO_ERR_TOO_LONG` — верните Circular или поставьте SMALLBUF 0.
* Конец звука определяется по `ap_st.played >= total`, а не по приходу TxCplt:
  в circular-режиме передача не завершается никогда. Хвост — тишина, поэтому
  точность окончания — половина буфера (93 мс), щелчка нет.
* **Ретраи чтения**: одиночный сбой SPI-чтения (типично под отладчиком, когда
  halt приходится на обмен) не рвёт звук — `ext_read()` повторяет попытку до
  `VECTOR_SF_READ_RETRY` раз (default 3, между попытками 2 мс сна потока).
  Успешное восстановление видно в логе: `ext_read: recovered after N retry`.

### Что нужно в CubeMX (обязательно)

**SAI1_A → DMA Settings → GPDMA1 Channel11 → Mode = Circular.**

На U5 у GPDMA нет классического circular — он делается связным списком, и куб
генерирует `HAL_DMAEx_List_BuildNode()` + `HAL_DMAEx_List_SetCircularModeConfig()`,
после чего `hdmatx->Mode == DMA_LINKEDLIST_CIRCULAR`. Именно в этом режиме HAL
**не гасит SAI** по завершении блока, поэтому стыки кусков без щелей и щелчков.

## 4. Набор звуков и мастер-файлы

Индекс звука = порядок файла в команде сборки; имена и `SND_*` генерируются в
`audio_ids.h` автоматически.

| idx | имя (`SND_*`) | файл | содержание |
|---|---|---|---|
| 0 | `SND_B_CLICK` | `b_click.wav` | короткий клик |
| 1 | `SND_C_VOICE_GAS` | `c_voice_gas.wav` | голосовое «газ» |
| 2 | `SND_D_MYVOICE` | `d_myvoice.wav` | голос ~8 с (проверяет стриминг) |

**Важно:** в репозитории лежат wav-файлы ещё от 16-кГц сборки. Для нового
качества пересоздайте их из оригиналов в 44.1 кГц/16 бит/моно, например sox:

```bash
sox my_voice_44k.wav -r 44100 -c 1 -b 16 tools/d_myvoice.wav     # из исходной записи
sox input-any.wav    -r 44100 -c 1 -b 16 tools/c_voice_gas.wav   # TTS/запись → 44.1к
```

(Из 16-кГц `d_myvoice.wav` апсемплинг качества не добавит — ищите исходник
`my_voice_44k.wav`, которым звук заливали в первый раз.)

Если пересобрать wav нечем, образ можно собрать и из текущих файлов — звук
останется прежним по качеству, но частота образа будет честной 44.1 кГц:

```bash
python tools/pack_sounds.py tools/b_click.wav tools/c_voice_gas.wav tools/d_myvoice.wav --out tools/sounds.bin
```

## 5. Управление

### Индексы, очередь и повтор

Слоя «состояний» (`audio_set_state()` / `ap_state_map[]`) больше нет: плеер
играет звуки **по индексу** в образе, и порядок воспроизведения не важен.

Как индекс превращается в адрес во внешней flash (перебора нет):

1. `load_image()` вызывается **один раз** из `audio_init()` (и по явному
   запросу из `audio_reload_image()`) и читает с адреса `AUDIO_IMG_BASE_ADDR`
   заголовок (24 байта: magic, version, `count`, CRC32 таблицы) и таблицу
   записей (`count × 36 байт`), проверяет CRC и распаковывает записи в
   RAM-массив `ap_tab[32]`: `offset`, `length`, `samples`, `rate`, `ch`, `fmt`,
   `crc`, `name[16]`. Цена в RAM ≈ 1.2 КБ + столько же временного буфера.
2. Дальше `start_now(idx)` — это `idx >= ap_hdr.count ? AUDIO_ERR_BAD_INDEX
   : ap_tab[idx]`, а адрес данных = `AUDIO_IMG_BASE_ADDR + e->offset`.
   То есть обращение к звуку №4 стоит столько же, сколько к №0: смещения
   абсолютные, «пролистывать» предыдущие не нужно.

| Вызов | Что делает |
|---|---|
| `audio_play(idx)` | в очередь: сыграет **после** текущего (если занято — в один слот ожидания `ap_pending_idx`, последняя команда побеждает) |
| `audio_play_now(idx)` | **прервать** текущий и сразу играть `idx` — одна команда очереди `CMD_PLAY_NOW` |
| `audio_play_name("zvonok_1")` | то же по имени: единственный линейный перебор в плеере (≤32 записи × 16 байт в RAM) |
| `audio_stop()` | стоп сейчас + очистка очереди, отложенного звука и текущего повтора |
| `audio_set_loop(1)` | повторять **последний запущенный** звук с паузой `VECTOR_AUDIO_LOOP_PAUSE_MS` (сигнализация «один звук по кругу»); по умолчанию выключен |

Повтор взводится для последнего успешно стартовавшего звука, поэтому
`audio_set_loop(1)` можно вызвать и заранее — зациклится то, что сыграют
первым. Одноразовые `audio_play()`/`audio_play_now()` встраиваются в повтор:
звучат вместо него, затем повтор продолжается.

### API

```c
audio_play(SND_PHONE_1);      /* в очередь: сыграет после текущего          */
audio_play_now(SND_KOLOKOL_1);/* прервать текущий и сразу играть этот       */
audio_play_name("zvonok_1");  /* то же по имени из таблицы образа           */
audio_stop();                 /* стоп сейчас + очистка очереди и повтора    */
audio_beep();                 /* аварийный писк из внутренней flash         */
audio_set_loop(1);            /* повторять последний запущенный звук        */
audio_set_loop_pause(500);    /* пауза между повторами, мс                  */
audio_set_volume(80);         /* программная громкость 0..100               */
audio_image_ok(); audio_count(); audio_name(i);   /* справка по образу      */
audio_reload_image();         /* перечитать таблицу (образ перезаписали на
                                 живом устройстве)                          */
```

Контекст вызова `audio_play/play_now/stop/set_loop/beep` — любой (поток или
ISR): это неблокирующие `tx_queue_send` + `tx_semaphore_put`, глубина очереди
`AUDIO_QUEUE_LEN = 8`.

### Кнопки (`VECTOR_AUDIO_DEMO_KEYS = 1`, тестовый режим)

| Кнопка | Действие |
|---|---|
| BUTTON1 (PB1) | перебор **всех** звуков образа по кругу: `audio_play_now(idx)` — прерывает текущий и сразу играет следующий (kolokol_1 → kolokol_2 → phone_1 → phone_2 → zvonok_1 → снова #0). Индекс по модулю `audio_count()`, поэтому состав образа может быть любым; текущий индекс — в `demo_status.sound_index` |
| BUTTON2 (PB2) | play/stop: если плеер играет (`audio_is_playing()`) — `audio_stop()` (стоп сейчас + очистка очереди и текущего повтора), если тишина — `audio_play_now()` звука, на котором остановилась BUTTON1 (после старта, когда BUTTON1 ещё не нажимали, — звук #0). Состояние берётся из плеера, а не из своего флага, поэтому кнопка не «промахивается» после того, как звук закончился сам; зеркало для отладчика — `demo_status.playing` |
| BUTTON3 (PB3) | тест громкости: цикл 100 → 75 → 50 → 25 → 0 → 100 %, текущее значение в `demo_status.volume_percent`, применение видно в логе строкой `volume NN% (q15=...)` |

Для серии поставьте `VECTOR_AUDIO_DEMO_KEYS 0` — кнопки отдадутся вашему
обработчику, плеер управляется только API.

## 6. Пересборка образа и запись во внешнюю flash

```bash
# 1. собрать образ (44100 Гц — значение по умолчанию):
python tools/pack_sounds.py tools/b_click.wav tools/c_voice_gas.wav tools/d_myvoice.wav --out tools/sounds.bin
#    -> tools/sounds.bin + tools/sounds.bin.manifest.txt
#    -> перегенерируется Core/VectorLib/Audio/Inc/audio_ids.h

# 2. пересобрать прошивку MCU (индексы SND_* могли измениться).

# 3. записать sounds.bin во внешнюю flash программатором (адрес 0x00000000):
#    STM32CubeProgrammer + external loader из Tools/ExtLoader_MX25R64.
#    Пошагово: docs/FLASHING.md, разделы 0-1.

# 4. (только если меняли частоту) перегенерировать аварийный писк:
python tools/gen_beep.py --rate 44100
```

Прошивка при старте читает заголовок и таблицу образа из внешней flash и
проверяет magic/version/CRC32/частоту. Валиден → `image ok=1 sounds=N`;
нет → играет только аварийный писк и в логе причина:

| Строка лога | Смысл |
|---|---|
| `image header bad: magic=...` | во flash не образ sounds.bin (пусто/мусор) — записать через программатор |
| `image CRC mismatch` | образ битый/недописанный — перезаписать |
| `image rate mismatch` | образ собран с другой частотой — пересобрать `--rate 44100` |
| `image: header read fail` | внешняя flash не читается (см. `probe rc=` в логе старта) |

### Карта внешней flash (8 МБ, `sfmap.h`)

```
0x000000  SOUNDS  4 МБ    sounds.bin целиком   <- пишет программатор (FLASHING.md)
0x400000  CONFIG  4 КБ    конфигурация         <- пишет только прошивка
0x401000  LOG     ~3.9 МБ кольцевой журнал     <- пишет только прошивка
```

Область SOUNDS при записи образа программатором стирается только в пределах
файла; CONFIG/LOG не затрагиваются (полный chip erase из CubeProgrammer
сотрёт и их — обычно не нужен).

## 7. Диагностика

Время в логе — тик ThreadX (`[сек.мс]`, разрешение 10 мс; до планировщика
`[0.000]`). Других источников времени у приложения нет (см. SYSTEM.md).

### 7.1 Писков нет вообще → аналоговая часть

`VECTOR_AUDIO_SELFTEST = N` играет N писков **до старта RTOS** (пауза ~300 мс),
причём цикл обрывается на первом же сбое — поэтому по услышанному и по логу
место проблемы определяется однозначно. Писк идёт из const-массива во
внутренней flash напрямую в SAI-DMA: внешняя flash, образ, очередь и поток
плеера в проверке не участвуют.

| Что слышно | Строка лога | Возврат | Где проблема |
|---|---|---|---|
| все N писков | `selftest: done, guard=...` (N раз) | 0 | цифровая часть рабочая → аналог: `SD_MODE` (PC9), питание усилителя, обвязка, динамик |
| ни одного | `selftest: SAI DMA start FAIL hal=N` | 1 | `HAL_SAI_Transmit_DMA` отказала: SAI не инициализирован или канал занят |
| частая «очередь» писков ~1 с и тишина | `selftest: DMA started but NOT finished (GPDMA1_Channel11_IRQn?)` | 2 | circular DMA прокручивает писк по кругу, но прерывание завершения не приходит → в NVIC не включён `GPDMA1_Channel11_IRQn` |

Дополнительно:

1. `SD_MODE` (PC9) = High? (CubeMX: GPIO output level = High; в коде страховка
   в `vector_board_init()`.)
2. Куб: SAI1 Mode = Master, I2S standard, 16-bit, 2 слота, Mono,
   Audio Frequency = 44.1 kHz; пины PA8=SCK, PA9=FS, PA10=SD.
3. Пауза между писками отсчитывается циклами ядра (`board_delay_cycles`),
   поэтому по ней видно реальную частоту SYSCLK: при заниженной вдвое она
   растягивается до ~600 мс. Сам писк всегда 240 мс — его темп задаёт SAI.

### 7.2 Писки есть, звука из образа нет

Порядок по логу:

```
probe rc=0 jedec=c2 28 17      <- внешняя flash жива (иначе SPI1/CS PA4/питание)
image ok=1 sounds=5            <- образ валиден (иначе строка причины выше)
play #2 'd_myvoice' stream 358306 samples @44100 Hz (chunk 4096)
```

* Нет строки `stream` в `play #...` → SAI DMA не в circular-режиме
  (раздел 3, «Что нужно в CubeMX»).
* `start #N failed, err=4 (io)` → чтение flash/DMA; смотрите
  `audio_status.last_error`, `sf_dbg_*`, строки `ext_read: recovered` (редкие
  транзиенты под отладчиком — норма, они теперь ретраятся).
* `watchdog: stuck sound killed` → не пришёл колбэк завершения DMA: NVIC
  GPDMA1_Channel11, ошибки SAI (`HAL_SAI_ErrorCallback`).
* Звук «заикается» → растёт `audio_status.cnt_underruns`: кто-то долго держит мьютекс
  шины (журнал/конфиг) или поднимите `VECTOR_AUDIO_STREAM_CHUNK` до 8192.

### 7.3 Счётчики (Expressions)

| Переменная | Смысл |
|---|---|
| `audio_status.output` | что звучит: `AUDIO_OUT_SILENT` / `_SOUND` / `_ALARM_BEEP` (прежнее `-1 / >=0 / -2`) |
| `audio_status.sound_index` | индекс звука в образе; `-1`, если сейчас не звук образа |
| `audio_status.boot_stage` | `AUDIO_BOOT_INIT` / `_IMAGE_OK` / `_IMAGE_BAD` / `_RUNNING` |
| `audio_status.cnt_commands / cnt_started / cnt_played` | команд принято / DMA стартовала / звук доигран |
| `audio_status.last_error / sai_error_code / cnt_errors` | код `audio_err_t` / сырой `SAI.ErrorCode` / число ошибок |
| `audio_status.cnt_underruns / cnt_watchdog / cnt_dropped / cnt_loops` | заикания стрима / убитые watchdog / вытесненные play / повторы цикла |
| `audio_status.loop_enabled / loop_index / loop_next_at_ms` | повтор: включён / какой звук / когда следующий |
| `sf_probe_rc, sf_jedec[3]` | жива ли внешняя flash (`C2 28 17`, `rc=0`) |
| `ext_dbg_*` | состояние журнала/конфига во внешней flash |
| `demo_status` | доходят ли нажатия кнопок (EXTI/уровень/антидребезг) |
| `ub_*` | счётчики моста UART4↔USART2 (мост больше ничего не логирует) |

Старые имена (до v14) → новые: все 14 переменных `audio_dbg_*` и внутренние
дубли (`ap_playing_idx`, `ap_loop_*`, `ap_img_ok`) заменены ОДНОЙ структурой
`audio_status`. Сохранённые Expressions нужно поправить так:

| Было | Стало |
|---|---|
| `audio_dbg_cur_idx` (`-1` тишина, `-2` писк, `>=0` звук) | `audio_status.output` (`AUDIO_OUT_SILENT` / `AUDIO_OUT_ALARM_BEEP` / `AUDIO_OUT_SOUND`) + `audio_status.sound_index` |
| `audio_dbg_boot_stage` (0..3) | `audio_status.boot_stage` (`AUDIO_BOOT_INIT` / `_IMAGE_OK` / `_IMAGE_BAD` / `_RUNNING`) |
| `audio_dbg_keys` / `_last_cmd` | `audio_status.cnt_commands` / `last_command` (`AUDIO_CMD_*`) |
| `audio_dbg_started` / `_played` / `_errors` | `audio_status.cnt_started` / `cnt_played` / `cnt_errors` |
| `audio_dbg_last_err` (в т.ч. `0x1000|ErrorCode`) | `audio_status.last_error` + `audio_status.sai_error_code` |
| `audio_dbg_underrun` / `_stuck` / `_dropped` / `_loops` | `audio_status.cnt_underruns` / `cnt_watchdog` / `cnt_dropped` / `cnt_loops` |
| `audio_dbg_wakes` / `_timeouts` | `audio_status.cnt_wakes` / `cnt_wake_timeouts` |
| `demo_dbg_*` | `demo_status.*` (`cnt_edges`, `cnt_pressed`, `cnt_inactive_level`, `cnt_debounced`, `last_pin`, `sound_index`, `volume_percent`, `playing`) |

В коде вместо сравнений с `-1/-2` — `audio_is_playing()` (звучит звук образа),
`audio_is_busy()` (звучит что-либо), `audio_get_output()`.

## 8. Значения по умолчанию (`Core/VectorLib/Inc/vector_config.h`)

| Макрос | Значение | Смысл |
|---|---|---|
| `VECTOR_AUDIO_STREAM` | `1` | стриминг кусками через circular DMA |
| `VECTOR_AUDIO_STREAM_CHUNK` | `4096` | сэмплов в половине буфера (93 мс @44.1 кГц, 16 КБ RAM) |
| `VECTOR_AUDIO_STREAM_SMALLBUF` | `1` | буфер = 2 куска (16 КБ вместо 131 КБ) |
| `VECTOR_SF_READ_RETRY` | `3` | повторы сбойного чтения внешней flash (1..16) |
| `VECTOR_AUDIO_LOOP_PAUSE_MS` | `500` | пауза между повторами |
| `VECTOR_AUDIO_SELFTEST` | `0` | писков при старте (до RTOS) |
| `VECTOR_AUDIO_BOOT_PLAY` | `0` | что сыграть при старте |
| `VECTOR_AUDIO_DEMO_KEYS` | `1` | тестовые кнопки PB1/PB2/PB3 |

Factory-переключателей (`VECTOR_AUDIO_FACTORY_*`) больше нет: образ во
внутреннюю flash не линкуется и при старте не записывается (docs/FLASHING.md).

## 9. Ограничения и что дальше

* Один звук за раз: буфер и SAI общие, микширования нет.
* Только моно 16 бит PCM (`AUDIO_FMT_PCM16`); формат IMA-ADPCM в таблице
  образа зарезервирован (`AUDIO_FMT_ADPCM_IMA`) — при желании даст в 4 раза
  больше звуков во flash ценой CPU на декодирование.
* Хочется ещё качества: путь один — 24-битные мастер-файлы + расширение
  формата образа и SAI до 24/32-битных слотов (MAX98357A их принимает).
  Для голосовых сообщений через малогабаритный динамик 16 бит/44.1 кГц —
  потолок слышимой разницы.
