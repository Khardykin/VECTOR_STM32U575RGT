# Как запустить звук: управление плеером и значения по умолчанию

## 1. Три способа запустить звук

### а) Из своего кода (основной способ)

```c
#include "audio_player.h"

audio_play(SND_C_VOICE_GAS);     /* по имени из audio_ids.h - в очередь      */
audio_play(2);                   /* то же самое по индексу                  */
audio_play_name("c_voice_gas");  /* по строке (ищет в таблице образа)       */

audio_set_state(1);              /* СМЕНА РЕЖИМА: прерывает текущий звук и
                                    играет звук состояния 1                  */
audio_stop();                    /* стоп сейчас + очистить очередь          */
audio_beep();                    /* аварийный писк из внутренней flash      */

audio_set_volume(70);            /* 0..100 %, применится со следующего звука */
```

Звать можно **из потока и из ISR**: функции кладут команду в очередь
ThreadX и взводят семафор, ничего блокирующего там нет. Сам звук читает из
flash и запускает DMA только поток `Audio Player`.

### б) Кнопками (тестовый режим, `VECTOR_AUDIO_DEMO_KEYS = 1`)

| Кнопка | Пин | Действие |
|---|---|---|
| BUTTON1 | PB1 | цикл состояний `0 → 1 → 2 → 0`, звук нового состояния стартует сразу |
| BUTTON2 | PB2 | следующий звук образа по кругу (0,1,2,3,0,…) |
| BUTTON3 | PB3 | стоп |

### в) Автоматически при старте (для проверки)

`VECTOR_AUDIO_BOOT_PLAY` в `vector_config.h`:

| Значение | Что делает |
|---|---|
| `0` | ничего (боевой режим: тишина до первой команды) |
| `1` | играет звук состояния 0 (`a_gas`) — проверяет **весь** тракт: внешняя flash → чтение → громкость → SAI/DMA → усилитель |
| `2` | играет звук #0 напрямую (то же, но без таблицы состояний) |
| `3` | **сейчас по умолчанию**: аварийный писк из внутренней flash — проверяет выходной тракт (SAI, DMA, усилитель, `SD_MODE`), вообще не трогая внешнюю память |

Логика такая: если при `3`писка нет — проблема в SAI/усилителе (или `SD_MODE`
на PC9 не поднят), внешняя flash ни при чём. Если писк есть, а при `1` тишина —
не читается образ из внешней flash (смотрите `sf_probe_rc`, `audio_dbg_boot_stage`).

## 2. Что лежит в образе и какие значения по умолчанию

Образ `sounds.img` во внешней flash (собран `tools/pack_sounds.py`), 4 звука
по 8 кГц моно 16 бит — это `audio_ids.h`, он генерируется вместе с образом:

| idx | имя (`SND_*`) | длительность |
|---|---|---|
| 0 | `a_gas` (`SND_A_GAS`) | 1.85 с |
| 1 | `b_click` (`SND_B_CLICK`) | 0.06 с |
| 2 | `c_voice_gas` (`SND_C_VOICE_GAS`) | 2.20 с |
| 3 | `d_myvoice` (`SND_D_MYVOICE`) | 8.10 с |

**Состояния** (таблица `ap_state_map[]` в `audio_player.c`):

| состояние | звук | откуда |
|---|---|---|
| 0 | `SND_STATE_DEFAULT_0` = `SND_A_GAS` (idx 0) | генерируется `pack_sounds.py` |
| 1 | `SND_STATE_DEFAULT_1` = `SND_B_CLICK` (idx 1) | то же |
| 2 | `AUDIO_STATE_SILENT` (0xFFFF) = тишина | зашито |

Значения по умолчанию при включении:

| Переменная | Значение | Смысл |
|---|---|---|
| `ap_state` | `0` | устройство в состоянии 0; **сам по себе звук при этом НЕ играется** — нужен вызов `audio_set_state()` / кнопка / `VECTOR_AUDIO_BOOT_PLAY` |
| `ap_vol_q15` | `32767` | громкость 100 % |
| `ap_playing_idx` | `-1` | ничего не играет |
| `ap_pending_idx` | `-1` | нет отложенного звука |
| `audio_dbg_boot_stage` | `1` | образ найден и валиден (норма); `2/4` — образа нет |

Хотите другую привязку состояний к звукам — подставьте имена из `audio_ids.h`:

```c
static const uint16_t ap_state_map[3] = {
  SND_D_MYVOICE,        /* состояние 0 */
  SND_C_VOICE_GAS,      /* состояние 1 */
  AUDIO_STATE_SILENT    /* состояние 2 = тишина */
};
```

Есть защита на этапе компиляции: если индекса нет в текущем образе, сборка не
пройдёт (`ap_state_assert0/1`).

## 3. Разница между `audio_play()` и `audio_set_state()`

| | `audio_play(id)` | `audio_set_state(st)` |
|---|---|---|
| текущий звук | **доигрывает до конца** | **прерывается немедленно** |
| новый звук | стартует после текущего | стартует сразу |
| очередь | очищается только по `audio_stop()` | очищается (старые команды сбрасываются) |
| запоминается | нет | да: `audio_get_state()` вернёт `st` |
| слот ожидания | один (`ap_pending_idx`): второй `play` подряд заменяет отложенный, счётчик `audio_dbg_dropped` | — |

Для «сигнализации о состоянии» правильнее `audio_set_state()`, для разовых
подсказок и кликов — `audio_play()`.

## 4. Ограничения текущей схемы

* Длина одного звука ≤ 65535 сэмплов = **8.19 с** при 8 кГц: звук читается
  **целиком** в один RAM-буфер `ap_buf[65535]` (131 070 Б) и уходит в SAI одной
  DMA-транзакцией. `d_myvoice` (8.10 с) впритык укладывается.
* Одновременно играет только один звук: буфер один.
* Частота фиксирована конфигом SAI (8 кГц, I2S 16 бит, моно). Звук с другой
  частотой в образе будет проигран с неверным темпом — `pack_sounds.py` приводит
  всё к 8 кГц, так что на практике этого не возникает.
* Длинные записи (минуты) требуют стриминга: circular DMA + подкачка половин
  буфера из flash. Это следующий этап, см. `docs/FIX_REPORT.md`, раздел 9.

## 5. Если звука нет — порядок проверки

| Шаг | Что смотреть | Норма |
|---|---|---|
| 1 | лог `probe rc=0 jedec=c2 20 17` | внешняя flash отвечает |
| 2 | `audio_dbg_boot_stage` | `1` (образ найден) или `5` (рабочий цикл) |
| 3 | `VECTOR_AUDIO_BOOT_PLAY = 3` → писк при старте | есть → SAI/усилитель живы |
| 4 | `SD_MODE` (PC9) | должен быть `1`, иначе усилитель в shutdown |
| 5 | `demo_dbg_press` / `audio_dbg_keys` | растут при нажатии кнопки |
| 6 | `audio_dbg_started` / `_played` | стартовало / доиграло |
| 7 | `audio_dbg_errors` / `_last_err` | код ошибки (`audio_err_t`) или `0x1000|SAI.ErrorCode` |
| 8 | `audio_dbg_stuck` | >0 — не пришёл колбэк завершения SAI-DMA |

Коды `audio_err_t`: `1` = нет образа, `2` = неверный индекс, `3` = звук длиннее
буфера, `4` = ошибка чтения flash или запуска DMA, `5` = очередь полна.

## 6. Как добавить свой звук

```
tools/pack_sounds.py  <ваши .wav>  ->  build/sounds.img + audio_ids.h
tools/bin2c.py        sounds.img   ->  audio_factory_image.c  (195 КБ const)
```

`audio_ids.h` пересоздаётся вместе с образом, поэтому `SND_STATE_DEFAULT_0/1`
и enum `SND_*` обновятся сами. При старте прошивка сравнит образ во внешней
flash и, если его нет или он битый, запишет встроенный (factory-режим,
`VECTOR_AUDIO_FACTORY_EMBED`). Подробнее — `docs/FLASH_PROGRAMMING.md`.
