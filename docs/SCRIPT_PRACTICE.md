# Тренировка со скриптами: задания и самопроверка

Цель — чтобы вы уверенно собирали и проверяли образ звуков сами, без меня.
Все команды даны для **cmd** из корня проекта; маски `*.wav` скрипты раскрывают сами.

Перед стартом: `python --version` → должен быть Python 3.8+. Если команда не найдена —
установите с python.org, поставив галку **Add python.exe to PATH**.

Результаты заданий (вывод команд или полученные файлы) коммитьте в репозиторий —
я проверю и скажу, где верно, где нет.

---

## Задание 1. Осмотр существующего образа

```bat
python tools\pack_sounds.py tools\sounds.img --check
```

**Ожидаю увидеть:** `count=3`, `table_crc=OK`, три строки с именами `a_gas`, `b_click`,
`c_voice_gas`, длинами 29536 / 960 / 35200 байт и `crc=OK` у каждой.

**Вопрос на понимание:** почему у `a_gas` длина 29536 байт, если исходный WAV длился
1.85 с при 16 кГц? (Ответ: образ собран с `--rate 8000`, сэмплов стало 14768, по 2 байта.)

## Задание 2. Детерминизм и паспорт сборки (manifest)

```bat
python tools\pack_sounds.py tools\a_gas.wav tools\b_click.wav tools\c_voice_gas.wav tools\d_myvoice.wav --out build\rb.img
fc /b tools\sounds.img build\rb.img
type build\rb.img.manifest.txt
```

**Ожидаю:** файлы **идентичны** (committed `sounds.img` собран без `--gain`), а в
manifest видно порядок файлов, sha256 каждого исходника и sha256 результата.

**Эксперимент, объясняющий прошлую ошибку:** пересоберите то же самое с `--gain 2.0`
и сравните с `tools\sounds.img` — байты **разойдутся**, хотя список файлов тот же.
Детерминизм означает «те же входы И те же параметры», а не «те же файлы».
Сравнивать образы вслепую через `fc /b` нельзя — сначала сверьте manifest'ы:
в них написаны rate и gain, которыми собирался каждый образ.

**Вопрос:** поменяйте порядок двух файлов местами, пересоберите и посмотрите
`--check`. Что случилось с индексами и почему после этого старый вызов
`audio_play(2)` заиграет не тот звук?

## Задание 3. Громкость и клиппинг (`--info` без сборки)

```bat
python tools\pack_sounds.py tools\b_click.wav --info
python tools\pack_sounds.py tools\b_click.wav --gain 3 --info
python tools\pack_sounds.py tools\b_click.wav --gain 10 --info
```

**Ожидаю:** в первом выводе пик около 20–25% FS; при `--gain 3` — около 65–70% и
`клиппинг 0`; при `--gain 10` — пик упрётся в 100% и появится `клиппинг N` с N > 0.

**Вопрос:** почему клиппинг — это плохо на слух и почему `--gain` лучше делать при
сборке, а не крутить `audio_set_volume()` вверх в рантайме?

## Задание 4. Ловушка частоты

```bat
python tools\pack_sounds.py tools\a_gas.wav --rate 16000 --out build\s16.img
python tools\pack_sounds.py build\s16.img --check
```

**Ожидаю:** в таблице `rate=16000`. А теперь подумайте: SAI1 у вас настроен на 8 кГц
(CubeMX → SAI1 AudioFrequency = 8K). Что услышите, если прошить `s16.img` вместо
`sounds.img`? (Ответ: сирена проиграется в два раза быстрее и на октаву выше — SAI
будет съедать 16-килогерцевые сэмплы со скоростью 8000 в секунду.)

**Вывод:** частота образа и частота SAI обязаны совпадать; pack_sounds по умолчанию
льёт в 8000 — под текущую настройку.

## Задание 5. Добавить свой звук

1. Добудьте любой WAV (голос через Silero/Yandex SpeechKit, эффект с freesound.org,
   или запишите диктофоном и сконвертируйте). Требования к исходнику минимальны:
   16 бит/сэмпл; каналы и частота любые — скрипт сам сведёт в моно и пересемплирует.
2. Положите его в `tools/` под именем `d_myvoice.wav`.
3. Пересоберите образ, **добавив файл в конец списка**:

```bat
python tools\pack_sounds.py tools\a_gas.wav tools\b_click.wav tools\c_voice_gas.wav tools\d_myvoice.wav --out tools\sounds.img
python tools\pack_sounds.py tools\sounds.img --check
```

4. Закоммитьте новый WAV и новый `sounds.img`.

**Ожидаю:** `count=4`, у нового звука `crc=OK`, строка бюджета покажет, сколько секунд
ещё свободно во внешней flash. Индексы 0–2 не сдвинулись (файл добавлен в конец) —
поэтому старый код продолжил работать.

**Проверка на железе:** BUTTON2 теперь прокрутит и четвёртый звук.

## Задание 7. Вызов по имени через сгенерированный enum

Откройте `Core/Inc/audio_ids.h` — он создан скриптом при последней сборке. В нём
enum `SND_<ИМЯ> = порядковый номер` и таблица-комментарий (номер, имя, сэмплы,
секунды). Найдите в `audio_player.c` обработчик BUTTON2 и замените вызов по
индексу на вызов по имени:

```c
(void)audio_play(SND_D_MYVOICE);   /* вместо audio_play(ap_test_next_idx) */
```

Соберите проект. Теперь добавьте в команду сборки новый WAV **в середину** списка,
пересоберите образ и заголовок, верните в обработчике перебор по индексу и посмотрите:
`SND_D_MYVOICE` по-прежнему указывает на тот же звук, а «сырой» индекс 3 — уже нет.
Это и есть причина вызывать по имени. Закоммитьте получившийся `audio_ids.h`.

## Шпаргалка команд

| Хочу | Команда |
|---|---|
| посмотреть образ | `python tools\pack_sounds.py tools\sounds.img --check` |
| собрать образ | `python tools\pack_sounds.py tools\*.wav --out tools\sounds.img` |
| параметры WAV без сборки | `python tools\pack_sounds.py файл.wav --info` |
| паспорт сборки | `type tools\sounds.img.manifest.txt` |
| enum звуков | генерируется сам в `Core\Inc\audio_ids.h`, путь меняется `--ids-out` |
| усилить при сборке | `... --gain 3.0` |
| собрать на 16 кГц | `... --rate 16000` (и не забыть SAI1 на 16K в CubeMX) |
| WAV → C-массив (legacy) | `python tools\wav2c.py файл.wav --out путь.c --name имя` |
