# Инструменты для работы со звуком и прошивкой

## flash_sound.py

Запись образа звуков во внешнюю flash по Modbus.
py flash_sound.py <PORT> [--slave N] --file <IMAGE> [--chunk SIZE]

| Аргумент       | Обязательный | По умолчанию | Описание                                      |
|----------------|--------------|--------------|-----------------------------------------------|
| `<PORT>`       | да           | —            | COM-порт прибора (`COM4`, `COM5`…)            |
| `--slave`      | нет          | `100`        | Modbus-адрес трекера                          |
| `--file`       | да           | —            | путь к `sounds.bin`                           |
| `--chunk`      | нет          | `255`        | размер чанка записи, байт (макс. 255)         |

Коды возврата: `0` = успех, `1` = ошибка.


## test_sound_test.py

Проверка механики тестового воспроизведения (`ALERT_SOUND_TEST`) и содержимого всего образа. Секции A–E проверяют механику (одиночный прогон, цикл, перезапуск на ходу, клампинг индекса), секция S (`--all`) перебирает все клипы образа, секции F/G (`--interactive`) проверяют гейт `block_sound` и квитирование кнопкой.
py test_sound_test.py <PORT> [--slave N] [--clip N] [--all] [--sweep-timeout S] [--interactive] [--monitor]

| Аргумент             | По умолчанию | Описание                                                        |
|----------------------|--------------|-----------------------------------------------------------------|
| `<PORT>`             | —            | COM-порт (обязательный, позиционный)                            |
| `--slave`            | `0`          | Modbus-адрес                                                    |
| `--clip`             | `1`          | какой клип использовать в тестах B/E                            |
| `--all`              | выкл         | перебрать весь образ: каждый клип `#0…#(count-1)` одиночным прогоном |
| `--sweep-timeout`    | `30.0`       | секунд на один клип при `--all`                                 |
| `--interactive`      | выкл         | добавить тесты F (гейт `block_sound`) и G (кнопка)              |
| `--monitor`          | выкл         | только наблюдение за состоянием `sound_test` в реальном времени |

Коды возврата: `0` = все PASS, `1` = есть FAIL.


## who_is_beeping.py

Показать, какой фоновый статус перехватит индикацию, когда тест её освободит. Объясняет писк между клипами: читает `Config_common.StateErr` (регистры `0x0005/0x0006`) и расшифровывает биты. Помечает `[ПАЧКА]` у статусов с `burst > 0` (ошибки прибора, батарея) — именно они дают несколько писков подряд.
py who_is_beeping.py <PORT> [--slave N]


## test_block_timer.py

Проверить, что 30-секундный таймер `TIMER_RTC_DATA_EXCHANGE_END` корректно снимает `block_sound` включая зеркало `sys_state.block_sound`. Ставит `0x0058 = 1`, ждёт 35 с без обмена, читает обратно. FAIL = блокировка воскресает через 50 мс (зеркало не обнулено в `audio_sound_block_reset()`).
py test_block_timer.py <PORT> [--slave N]


## pack_sounds.py

Сборка WAV-файлов в образ `sounds.bin` для внешней flash. Формат: 44.1 кГц / 16 бит / моно. Генерирует сопутствующие файлы: `sounds.bin.manifest.txt` (паспорт сборки с SHA256), `audio_ids.h` (enum `SND_*`).
py pack_sounds.py <WAV...> --out <BIN> [--rate 44100] [--gain 1.0]
py pack_sounds.py <BIN> --check
py pack_sounds.py <WAV> --info

| Режим     | Команда                                            | Описание                                     |
|-----------|----------------------------------------------------|----------------------------------------------|
| Сборка    | `py pack_sounds.py *.wav --out sounds.bin`         | собрать образ из WAV                         |
| Проверка  | `py pack_sounds.py sounds.bin --check`             | парсить готовый образ, печать count/CRC/имён |
| Инфо      | `py pack_sounds.py file.wav --info`                | параметры WAV без сборки                     |


## flash_and_test.bat

Полный цикл «запись + тест» одним запуском. Запускать из папки `tools`. Без аргументов — интерактивный выбор COM-порта из списка доступных. Последовательный (один COM-порт = один процесс). Шаги: проверка порта → проверка образа (`--check`) → запись (`flash_sound.py`) → фоновые статусы (`who_is_beeping.py`) → тест (`test_sound_test.py --all`).
flash_and_test.bat [PORT] [SLAVE] [IMAGE] [CHUNK] [/I] [/T] [/Q]

| Аргумент   | По умолчанию  | Описание                                          |
|------------|---------------|---------------------------------------------------|
| *(без арг)*| —             | интерактивный выбор COM-порта из списка доступных |
| `PORT`     | —             | COM-порт (позиционный)                            |
| `SLAVE`    | `0`         | Modbus-адрес                                      |
| `IMAGE`    | `sounds.bin`  | файл образа                                       |
| `CHUNK`    | `255`         | размер чанка                                      |
| `/I`       | выкл          | интерактивный тест (гейт + кнопка)                |
| `/T`       | выкл          | только тест, пропустить запись                    |
| `/Q`       | выкл          | без вопросов и pause (автоматизация)              |

Коды возврата: `0` PASS, `1` FAIL, `2` отмена.


## Патчи прошивки (применяются один раз)

Все патчи идемпотентны: повторный запуск даёт `[SKIP уже]`, дублей не создаёт. После применения пересобрать и прошить MCU.

### apply_sndtest.py

Добавляет тестовое воспроизведение звука поверх реестра Alert. Создаёт статус `ALERT_SOUND_TEST` (высший приоритет), глобальный управляющий блок `sound_test_t`, API `SoundTest_Start/Stop/Active`, регистры Modbus `0x0060…0x006B` (req/stop/index/repeats/loop/active/source/last_index/cnt_start/cnt_done). Хук в `alert_indication_start()` подменяет канал и индекс клипа динамически (flash или beep при отсутствии образа). Кнопка закрывает тест целиком через `Alert_ButtonSoundMute()`. Тест разрешён на прогреве (`DEVICE_TURNED_ON_1`).
py tools/apply_sndtest.py

### apply_sweep_all.py

Добавляет регистр `0x006C count` (число звуков в образе, обновляется каждый такт `SoundTest_Tick` из `audio_count()`) и режим `--all` в `test_sound_test.py` для перебора всех клипов образа. Требует предварительно применённый `apply_sndtest.py`.
py tools/apply_sweep_all.py

### apply_errdump.py

Добавляет в `test_sound_test.py` расшифровку `StateErr` на baseline и после каждого завершения теста — показывает, какой фоновый статус перехватывает индикацию (источник писка между клипами). Опциональный, для удобства диагностики.
py tools/apply_errdump.py

### apply_ota_cleanup.py

Убирает дублирование стирания бутлоадера: удаляет небезопасный блок в `Vector_Options_System()` (не проверял `boot_flash_allowed()`, глотал ошибки через `(void)`), оставляет единственный путь через `ExecutePendingActions()`. Удаляет мёртвый `boot_flash_restore()` (бутлоадер не хранится во внешней flash, копия наружу не делается). Переименовывает `SF_BOOT_BASE/SIZE` → `SF_APP_STAGE_BASE/SIZE` в `sfmap.h` и зависимых файлах (адреса не меняются, только имя для ясности).

py tools/apply_ota_cleanup.py

### rename_flash_script.py

Переименовывает `test_flash_write_final.py` → `flash_sound.py` и обновляет ссылку в `flash_and_test.bat`. Слово «final» было артефактом итераций.
py tools/rename_flash_script.py

### create_tools_md.py

Создаёт этот файл (`tools/TOOLS.md`) одним вызовом. Для обновления документации после изменений в инструментах.
py tools/create_tools_md.py
